# ADR 0002 — Auth implementation choices

- **Status:** accepted
- **Date:** 2026-06-21
- **Phase:** 1 (Auth & users)

## Context

The spec (`docs/13-security.md` §2, `docs/04-api-reference.md` §2–3) fixes the auth model:
Argon2id, opaque server-side sessions in an httpOnly/Secure/SameSite=Lax cookie, deny-by-
default authz, login rate-limiting, forced change of the bootstrap admin password. A few
implementation details were left open.

## Decisions

1. **Argon2id via `hash-wasm` (pure WASM), not a native addon.** Avoids a second native
   build gate (we already manage `better-sqlite3`); identical behaviour on Windows dev and
   the Linux Docker image. Params: m=19456 KiB, t=2, p=1, 16-byte salt, PHC-encoded output
   (OWASP baseline). If throughput ever matters, swap to `@node-rs/argon2` behind the same
   `hashPassword`/`verifyPassword` interface in `src/lib/auth.ts`.

2. **Opaque session tokens, server-stored.** `sessions.id` is 32 random bytes (base64url)
   and doubles as the cookie value, signed by `@fastify/cookie` with `SESSION_SECRET`.
   Revocation is immediate (logout sets `revoked=1`; disabling a user fails session
   resolution). Absolute 30-day TTL; sliding renewal can be added later. Chosen over JWT so
   revocation needs no blocklist.

3. **`users.must_change_password` column added** (not in the original DDL). Set on the
   bootstrap admin and on admin password resets; cleared when the user sets their own
   password. Surfaced on `/api/auth/me` so the SPA can force the change screen. Data-model
   doc updated to match.

4. **Authz is middleware, deny-by-default.** `app.authenticate` / `app.requireAdmin`
   preHandlers (in `src/plugins/auth.ts`) resolve the cookie → user on each request. Public
   routes (`/api/health`, `/api/auth/login`, later `/api/branding`) simply omit the
   preHandler; everything else opts in. Admin routes add `requireAdmin` as a module-level
   `preHandler` hook.

5. **Login rate-limit cap is config-driven** (`LOGIN_RATE_MAX`, default 10/min/IP) so tests
   can set it high (flow tests) or low (the rate-limit test) deterministically.

6. **Migrations remain hand-authored SQL** applied by Drizzle's migrator (continuing the
   Phase-0 pattern): `0001_auth.sql` + a `meta/_journal.json` entry. This is a deliberate,
   working choice — but `pnpm db:generate` (drizzle-kit) will not diff correctly until
   someone backfills the `meta/000N_snapshot.json` files. **Follow-up for a future phase:**
   either backfill snapshots to adopt drizzle-kit generation, or keep hand-authoring (the
   migrator doesn't care). Tracked in PROGRESS.

## Consequences

- No native crypto build; one fewer cross-platform risk.
- Sessions are revocable and cheap to reason about.
- The `must_change_password` divergence is documented in two places (here + data model).
- Schema changes for now are hand-written DDL; keep them faithful to `03-data-model.md`.
